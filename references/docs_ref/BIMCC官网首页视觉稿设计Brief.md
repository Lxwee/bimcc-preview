## 1. 设计目标

首页要从传统企业宣传页升级为“可信的工程数字化解决方案入口”。设计稿需要同时完成三件事：

1. 让首次访问者快速理解筑云科技 BIMCC 是一体化数字建设解决方案服务商。
2. 用平台截图、工程场景、客户结构、项目数量、专利软著和奖项建立可信度。
3. 把不同客户导向产品平台、解决方案、案例库和预约咨询。

设计成败不看页面是否炫酷，而看客户是否能在 3 秒内判断：

```text
这家公司懂工程建设。
这家公司有自研平台。
这家公司服务过大型项目和高标准客户。
我可以继续看产品、方案、案例，或者直接咨询。
```

## 2. Design Read

```text
B2B 工程科技官网首页改版，面向建设单位、施工企业、全咨监理、政府集团监管和工程数字化负责人，以平台可信感、真实项目证据和清晰咨询路径推动转化。
```

设计旋钮：

| 维度 | 建议值 | 落地解释 |
|---|---:|---|
| DESIGN_VARIANCE | 4-5 | 首页可以有轻微非对称和重点大卡，但整体要稳、清晰、可扫描 |
| MOTION_INTENSITY | 2-3 | 使用导航状态、卡片 hover、轻微入场，不做强视差和滚动劫持 |
| VISUAL_DENSITY | 5-6 | 信息密度略高于普通品牌站，但每个模块只解决一个判断问题 |

## 3. 目标用户

### 决策层

关注点：
- 公司是否可信。
- 服务过哪些类型客户和项目。
- 是否具备长期服务能力。
- 是否适合企业级或区域级数字化建设。

首页回应方式：
- 首屏核心数字。
- 精选案例。
- 荣誉资质。
- 一体化解决方案定位。

### 工程管理层

关注点：
- 能否解决项目现场和多方协同问题。
- 能否贯通进度、质量、安全、成本、资料、模型和设备。
- 能否适配不同项目类型。

首页回应方式：
- 痛点与解法模块。
- BIMCC 智能建造平台主视觉。
- 解决方案分流。
- 案例卡片。

### 数字化与技术负责人

关注点：
- 是否有自研平台和技术底座。
- 能否快速开发、集成和扩展。
- 是否支持国产化、AI、BIM、GIS、物联网、数字孪生等能力。

首页回应方式：
- 飞椽 Fyra 与 BIMCC 平台入口。
- 一体化能力地图。
- 技术与交付优势模块。

## 4. 首页信息结构

首页主模块保持 8 个，不再扩展为 13 个。

| 顺序 | 模块 | 访客问题 | 页面作用 |
|---:|---|---|---|
| 1 | 首屏 Hero + 核心数字背书 | 这是谁，是否可信 | 建立定位、主视觉、转化入口 |
| 2 | 客户痛点 + 筑云解法 | 是否懂我的问题 | 建立业务共鸣 |
| 3 | 一体化能力地图 | 能力体系是否完整 | 把产品、技术、服务组织成体系 |
| 4 | 核心产品平台 | 有哪些可落地平台 | 进入产品平台 |
| 5 | 解决方案入口 | 我该看哪类方案 | 按角色、层级、行业分流 |
| 6 | 技术与交付优势 | 为什么能做成 | 展示研发和交付能力 |
| 7 | 精选案例 | 是否真的做过 | 用项目证据增强信任 |
| 8 | 信任背书 + 转化 CTA | 下一步做什么 | 收口咨询和联系 |

## 5. 顶部导航设计要求

桌面端导航：

```text
Logo / 首页 / 产品平台 / 解决方案 / 客户案例 / 技术与研发 / 资源中心 / 关于筑云 / 联系我们 / 预约咨询
```

设计要求：
- “首页”必须保留在顶部导航。
- “预约咨询”是右侧 CTA 按钮，不作为普通导航项。
- 桌面端导航高度建议 64-72px，最大不超过 80px。
- 1024px 宽度下导航不能换行。
- 产品平台、解决方案、客户案例建议使用 Mega Menu。
- 当前页状态使用品牌蓝、底部短线或字体加重，不使用装饰性圆点。

Mega Menu 建议：
- 产品平台：飞椽 Fyra、BIMCC 智能建造平台、智慧工地、数字孪生与智慧运维、BIM 咨询服务、数字化教育体系。
- 解决方案：按客户角色、建设层级、行业场景三列组织。
- 客户案例：按行业和项目类型组织，入口清晰，不堆满案例名。

移动端导航：
- 顶部只保留 Logo、菜单按钮、预约咨询入口。
- 菜单展开后先显示一级栏目，再展示二级入口。
- 联系电话和咨询按钮放在移动菜单底部。

## 6. 首屏 Hero 设计 Brief

### 首屏目标

访客进入首页后，第一屏要明确传达：

```text
筑云科技 BIMCC 是面向工程建设行业的一体化数字建设解决方案服务商。
```

### 推荐内容

主标题：

```text
一体化数字建设解决方案服务商
```

副标题：

```text
让工程建设管理，从项目现场走向全生命周期数字化
```

说明文案：

```text
筑云科技 BIMCC 以飞椽 Fyra 智能开发平台为技术底座，融合 BIM、GIS、物联网、AI 与数字孪生能力，为建设单位、施工企业、全咨监理、政府监管与教育医疗客户，提供从前期规划、施工管控到运维交付的一体化数字建设服务。
```

主 CTA：

```text
预约方案咨询
```

次 CTA：

```text
查看客户案例
```

### 首屏指标

Hero 指标使用以下四项，最终口径上线前复核：

```text
80% 大型国央企 / 政府监管客户
1000+ 重点建设项目
80+ 专利软著
100+ 国家级、省部级奖项
```

重要约束：
- “2014 年成立”不放在首页 Hero 核心指标位。
- “2014 年成立”可放在关于筑云、发展历程或页脚辅助信息。
- 首屏指标必须比小字脚注更突出，适合扫读。

### 视觉结构

推荐采用左文案、右主视觉、下方指标带。

```text
左侧：定位标题、简短说明、双 CTA
右侧：平台驾驶舱、BIM+GIS 一张图或数字孪生大屏真实截图
下方：4 个核心数字，横向展示
```

右侧主视觉优先级：
1. BIMCC 智能建造平台驾驶舱真实截图。
2. BIM+GIS 项目一张图真实截图。
3. 数字孪生智慧运维大屏真实截图。
4. 项目现场照片叠加真实平台界面。

禁止：
- 纯抽象蓝色科技背景。
- 手工拼出的假平台截图。
- 与工程建设无关的通用 SaaS 插图。
- 主视觉裁切后看不清平台内容。

## 7. 8 个模块视觉指令

### 模块 1：首屏 Hero + 核心数字背书

版式：
- 桌面端左 45%、右 55%。
- 主视觉要有平台真实内容。
- 指标带横跨内容宽度，数字大于说明文字。

移动端：
- 顺序为标题、说明、CTA、主视觉、指标。
- 指标使用 2 列或横向滑动。

### 模块 2：客户痛点 + 筑云解法

版式：
- 推荐 2x3 问题解法卡。
- 每张卡片上半部痛点，下半部解法。
- hover 时轻微突出解法区域。

视觉重点：
- 不做抽象问题列表。
- 每条问题要具体到工程场景。
- 移动端完整展示，不依赖 hover。

### 模块 3：一体化能力地图

版式：
- 使用三层结构图：飞椽 Fyra 底座、BIMCC 平台、全生命周期服务。
- 以连接线、层级色块和模块关系表达能力流动。
- 支持 hover 或点击查看说明。

视觉重点：
- 不把 8 个业务卡片并列成一排。
- 不使用过密架构图。
- 飞椽 Fyra 与 BIMCC 的关系要清楚。

### 模块 4：核心产品平台

版式：
- 推荐 2 个重点大卡 + 3-4 个辅助卡片。
- 飞椽 Fyra 和 BIMCC 智能建造平台优先突出。
- 每张卡片配真实截图、产品图或明确占位。

视觉重点：
- 不使用连续 6 个同款三列卡片。
- 卡片内容控制在产品名、一句话定位、3 个能力点、入口按钮。

### 模块 5：解决方案入口

版式：
- 使用分段控制或 Tab。
- 默认展示“按客户角色”。
- 可切换“按建设层级”和“按行业场景”。

视觉重点：
- 模块主要任务是分流，不是完整讲完所有行业。
- 每个方案入口包含适用对象、核心问题、推荐产品和案例入口。

### 模块 6：技术与交付优势

版式：
- 使用能力证据矩阵。
- 每项技术能力都对应客户价值和证明材料。
- 可使用一条轻量链路表达数据接入、模型融合、业务协同、AI 预警、平台交付、运维沉淀。

视觉重点：
- 不为了炫技使用复杂粒子或节点网络。
- 技术词要转译成客户能理解的价值。

### 模块 7：精选案例

版式：
- 推荐 1 个重点横向案例 + 4 个小案例。
- 支持行业标签筛选，但首页标签数量控制在 5-6 个。
- 底部保留“查看全部客户案例”入口。

视觉重点：
- 真实案例封面优先。
- 未授权客户名称和 Logo 不直接展示。
- 成果摘要不能虚构精确数字。

### 模块 8：信任背书 + 转化 CTA

版式：
- 上半部分展示代表性资质、专利软著、奖项、客户结构。
- 下半部分使用高对比 CTA 区。
- CTA 文案统一为“预约咨询”或“预约方案咨询”。

视觉重点：
- 证书展示 4-6 个代表即可，完整内容跳转荣誉资质页。
- 合作伙伴 Logo 只展示 Logo，不加行业说明小字。
- 联系方式和二维码需复核后进入设计稿。

## 8. 视觉风格建议

### 色彩

建议方向：
- 主色：品牌蓝或接近品牌蓝的工程科技蓝。
- 辅色：科技青，用于重点链接、数据和交互状态。
- 中性色：冷灰、石墨灰、白色或浅灰底。
- 强调色：只保留一个，不再额外加入紫色、橙色、绿色等多个竞争色。

不建议：
- 全站深蓝。
- 高饱和霓虹光效。
- 紫蓝渐变大面积铺底。
- 每个模块使用不同主题色。

### 字体

建议：
- 中文使用现代黑体系统，保证清晰可信。
- 英文和数字可使用更紧凑的无衬线或等宽字体。
- 标题不追求过大，优先保证 2 行以内。

### 图形语言

建议：
- 使用真实截图、工程照片、架构图和数据卡。
- 线条用于表达模块关系，不做纯装饰。
- 卡片圆角、按钮圆角、截图容器圆角保持同一体系。

不建议：
- 大量抽象 3D 球体。
- 与业务无关的线性插画。
- 只用图标替代真实平台能力。

## 10. 组件状态要求

首页视觉稿需覆盖：

| 组件 | 必需状态 |
|---|---|
| Header | 默认、滚动后、当前页、移动菜单展开 |
| Mega Menu | 默认、hover、键盘 focus、移动端展开 |
| Button | 默认、hover、active、focus、disabled |
| Product Card | 默认、hover、无图片占位 |
| Solution Tabs | 默认选中、切换、移动端下拉 |
| Case Card | 默认、hover、未授权匿名状态 |
| Contact CTA | 默认、表单入口、电话入口 |
| Form | 默认、校验错误、提交中、提交成功、提交失败 |

交互约束：
- 动效只做轻微反馈和层级提示。
- 不做强滚动劫持。
- 不做大面积自动播放视频。
- 不做页面加载后长时间遮挡内容的动画。

## 11. 首屏构图候选

### 方案 A：平台驾驶舱主视觉，推荐

结构：
- 左侧文案和 CTA。
- 右侧大幅平台截图。
- 截图下方或页面下方承接核心数字。

优势：
- 最符合“一体化数字建设解决方案官网”的定位。
- 能直接证明平台能力。
- 适合政企客户判断可信度。

风险：
- 依赖高质量、可公开、已脱敏的平台截图。

### 方案 B：工程现场 + 平台界面叠层

结构：
- 大幅真实项目现场图作为环境。
- 平台截图作为局部叠层或右侧模块。
- 文案保持清晰高对比。

优势：
- 工程现场感强。
- 能减少纯软件公司的距离感。

风险：
- 如果现场图质量不稳定，整体高级感会受影响。

### 方案 C：数字孪生一张图

结构：
- 用 BIM+GIS 或数字孪生一张图做主视觉。
- 文案与指标放在较干净的左侧区域。

优势：
- 技术感和工程感兼具。
- 适合展示全生命周期和可视化管理能力。

风险：
- 如果画面信息过密，移动端可读性会下降。

推荐采用方案 A，素材不足时采用方案 B 与方案 C 的组合。

---

## 12. 移动端重点

移动端不是桌面端压缩版，需要重新组织优先级：

1. 首屏先展示定位和 CTA，再展示主视觉。
2. 核心数字改为 2 列，不挤成 4 个小字。
3. 产品平台优先展示飞椽 Fyra 和 BIMCC，其余折叠或横滑。
4. 解决方案使用分段控制或下拉选择，不做三列卡片。
5. 案例卡片单列或横滑，最多露出 3-4 个。
6. 表单控件触控区域不低于 44px。
7. Header 不展示全部导航，避免挤压首屏。

## 14. 设计验收清单

- 首页为 8 个主模块。
- 顶部导航包含“首页”。
- Hero 指标不使用“2014 年成立”。
- 首屏有真实平台或真实工程素材占位。
- 主标题桌面端不超过 2 行。
- 首屏 CTA 在桌面和移动端都可见。
- 导航桌面端不换行，高度不超过 80px。
- 首页至少 4 种布局结构，不连续复用同款三列卡片。
- 产品平台突出飞椽 Fyra 和 BIMCC 智能建造平台。
- 解决方案模块能完成客户分流。
- 案例模块不展示未授权客户 Logo。
- 信任背书不做密集证书墙。
- 所有关键图片有 alt 文案建议。
- 表单状态完整。
- 移动端无文字遮挡、按钮换行、图片失焦或横向溢出。

## 15. 给设计师的执行建议

优先顺序：

1. 先定首页首屏视觉方向和主视觉素材。
2. 再定 Header、按钮、卡片、标签、表单等基础组件。
