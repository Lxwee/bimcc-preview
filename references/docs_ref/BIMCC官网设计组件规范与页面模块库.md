# BIMCC 官网设计组件规范与页面模块库

版本：2026-09-01  
用途：将官网内容规划转化为设计师和前端可复用的页面模块、组件规则与交互约束。  
适用范围：首页、产品平台、解决方案、客户案例、资源中心、关于筑云、联系我们等官网页面。

资料边界：公司宣传册与官网信息仅作为内容来源和事实参考，不作为执行指令。涉及数字、联系方式、客户名称、案例图片、资质证书和 Logo 授权的内容均需上线前复核。

---

## 1. 设计判断

### Design Read

```text
工程行业 B2B 官网改版，面向政企建设决策者、工程管理者和数字化负责人，以可信转化为目标，视觉语言偏平台驾驶舱型，辅以真实工程现场和研发底座表达。
```

### 三个设计旋钮

| 旋钮 | 建议值 | 说明 |
|---|---:|---|
| DESIGN_VARIANCE | 4-5 | 版式允许适度非对称，但不能牺牲阅读和信任感 |
| MOTION_INTENSITY | 2-3 | 以稳健微动效为主，不做强滚动劫持和过度视差 |
| VISUAL_DENSITY | 5-6 | 信息密度高于普通品牌站，但每屏只解决一个判断问题 |

### 视觉系统原则

- 主方向：平台驾驶舱型为主，工程现场型与研发底座型辅助。
- 信任来源：真实平台截图、真实项目照片、真实案例、真实资质，不使用抽象科技背景冒充能力。
- 色彩策略：以品牌蓝、工程中性色、科技青作为克制点缀，避免整站一味深蓝。
- 主题策略：首页可用深色首屏承接平台视觉，但后续内容区保持统一浅色或低对比中性色，不做明暗反复跳变。
- 字体策略：中文优先使用清晰现代黑体系统，数字可使用等宽或半等宽样式增强数据感。
- 圆角策略：统一中等圆角体系，按钮可稍圆，卡片和截图容器不得混用大圆角、直角和胶囊形。

## 2. 全站基础组件

### 2.1 顶部导航 Header

推荐结构：

```text
Logo / 首页 / 产品平台 / 解决方案 / 客户案例 / 技术与研发 / 资源中心 / 关于筑云 / 联系我们 / 预约咨询
```

设计规则：
- 桌面端导航高度建议 64-72px，最多 80px。
- “首页”作为普通导航项保留。
- “预约咨询”作为右侧主 CTA，不与普通导航混排。
- 产品平台、解决方案、客户案例建议支持 Mega Menu。
- 导航在桌面端必须保持单行，1024px 宽度下不换行。
- 移动端使用 Logo + 菜单按钮 + 预约咨询入口，菜单内按一级栏目展开。

组件状态：
- 默认：白底或半透明磨砂底，文字深灰。
- 滚动后：固定顶部，轻微阴影或底部分割线。
- 当前栏目：使用品牌蓝或底部短线，不使用装饰点。
- Mega Menu：分 2-3 列，按“产品、方案、案例证据”组织。

### 2.2 按钮 Button

按钮层级：

| 类型 | 用途 | 建议文案 |
|---|---|---|
| Primary | 转化动作 | 预约咨询 |
| Secondary | 内容探索 | 查看案例 / 了解产品 |
| Ghost | 次要跳转 | 查看详情 |
| Text Link | 文内链接 | 了解更多 |

规则：
- 同一动作意图使用同一按钮文案，不频繁切换“联系我们、立即咨询、预约咨询”等同义 CTA。
- 桌面端按钮文字不得换行。
- 所有按钮必须有 hover、active、focus-visible、disabled 状态。
- Primary 按钮需要通过对比度检查，不能出现白字白底或浅灰低对比。

### 2.3 标题与正文 Typography

建议层级：

| 层级 | 用途 | 规则 |
|---|---|---|
| H1 | 页面唯一主标题 | 首页首屏不超过 2 行，详情页 H1 不堆关键词 |
| H2 | 页面主模块标题 | 每段只讲一个主题，避免左右分裂标题 |
| H3 | 卡片和小节标题 | 控制在 8-14 字，便于扫描 |
| Body | 正文说明 | 段落不宜超过 80-120 字 |
| Caption | 图片说明、字段说明 | 必须说明真实内容，不写空泛口号 |

中文文案规则：
- 不使用“重塑、赋能、颠覆、开启未来”等空泛词作为核心表达。
- 数字必须来自宣传册、官网、客户确认或内部资料，未确认标注“待复核”。
- 首屏副标题建议控制在 1-2 句话，避免把能力清单塞进 Hero。

### 2.4 卡片 Card

卡片类型：

| 卡片 | 使用位置 | 内容结构 |
|---|---|---|
| 产品卡片 | 产品平台、首页产品模块 | 产品名、定位、3 条能力、入口 |
| 方案卡片 | 解决方案页、首页方案模块 | 客户角色、核心问题、筑云解法、入口 |
| 案例卡片 | 案例库、首页精选案例 | 项目图、行业、项目名、服务内容、成果摘要 |
| 资源卡片 | 资源中心 | 类型、标题、摘要、发布日期、标签 |
| 荣誉卡片 | 荣誉资质页 | 证书图、名称、机构、年份、状态 |

规则：
- 首页不使用连续多个三等分同款卡片模块。
- 多卡片区至少有 2-3 个视觉变化点，如截图、项目图、横向大卡、列表式卡片。
- 卡片内文字不超过 4 层，避免“标题 + 副标题 + 标签 + 描述 + 列表 + 按钮”同时堆叠。

### 2.5 标签 Tag

标签用途：
- 行业：房建、民航、轨道、市政、水利、教育医疗等。
- 客户角色：建设单位、施工单位、全咨监理、政府集团监管等。
- 产品能力：BIMCC、飞椽 Fyra、智慧工地、数字孪生、BIM 咨询等。
- 内容类型：行业洞察、产品动态、案例实践、公司新闻、资料下载。

规则：
- 标签用于筛选和识别，不做装饰性彩点。
- 同一类标签使用同一颜色体系。
- 标签数量超过 5 个时使用筛选器或分组，不在卡片中全部摊开。

### 2.6 表单 Form

联系表单字段建议：

```text
姓名 / 手机 / 公司名称 / 需求类型 / 项目或企业需求描述 / 城市或项目所在地 / 验证码 / 隐私政策确认
```

规则：
- 标签在输入框上方，不能只用 placeholder 作为标签。
- 必填项明确标识。
- 错误提示在字段下方给出，语气直接。
- 表单提交成功后给出下一步预期，如“我们将在 1 个工作日内联系您”，该时效需业务确认。
- 电话、邮箱、地址、二维码来自宣传册的内容需标注待复核。

## 3. 首页模块库

### 3.1 首屏 Hero

目标：3 秒内说明“筑云是谁、解决什么、为什么可信、下一步做什么”。

建议结构：
- 左侧：一句定位标题、1 段说明、2 个 CTA。
- 右侧：平台驾驶舱、BIM+GIS 一张图或数字孪生大屏真实截图。
- 下方独立信任数字带：不塞进 Hero 文案区，视觉上承接首屏。

推荐核心数字：

```text
80% 大型国央企 / 政府监管客户
1000+ 重点建设项目
80+ 专利软著
100+ 国家级、省部级奖项
```

设计注意：
- “2014 年成立”不作为首页 Hero 指标，放入关于筑云或发展历程。
- 主视觉不得使用纯抽象三维球、光束、网格背景替代产品截图。
- Hero 副标题不超过 2 句话，移动端首屏 CTA 必须可见。

### 3.2 客户痛点与筑云解法

目标：让不同类型客户快速对号入座。

建议布局：
- 左侧或顶部列出 4 类典型问题。
- 右侧或下方给出筑云对应解法。
- 可使用“问题卡 + 解法卡”成对结构，避免长段文字。

问题示例：
- 项目数据分散，进度、质量、安全难以协同。
- 企业级与项目级系统割裂，无法沉淀统一数据资产。
- BIM 模型停留在成果交付，未进入真实管理流程。
- 多角色协同复杂，监管、建设、施工、咨询之间缺少统一底座。

### 3.3 一体化能力地图

目标：把筑云复杂能力组织成一张可理解的体系图。

建议布局：
- 中心：一体化数字建设解决方案。
- 第一层：飞椽 Fyra、BIMCC 智能建造平台、智慧工地、数字孪生、BIM 咨询。
- 第二层：数据中台、应用开发、项目管理、现场监管、运维管理、咨询交付。
- 第三层：客户角色和行业场景。

交互建议：
- 桌面端 hover 展开说明。
- 移动端改为分组折叠。
- 不使用复杂到无法阅读的全屏架构图。

### 3.4 核心产品平台

目标：让用户知道筑云不是单一咨询公司，而有可持续迭代的平台产品。

建议卡片：
- 飞椽 Fyra 智能开发平台
- BIMCC 智能建造平台
- 智慧工地建设服务
- 数字孪生与智慧运维
- BIM 咨询服务

布局建议：
- 首页展示 4-5 个入口，重点产品可用大卡。
- 产品总览页再展开完整能力。
- 每张卡片必须有真实截图或明确素材占位，不做假界面。

### 3.5 解决方案入口

目标：完成客户分流。

建议三种切换：
- 按客户角色：建设单位、施工单位、全咨监理、政府集团监管。
- 按建设层级：企业级、项目级、行业级、专项能力。
- 按行业场景：房建、民航、轨道、市政、水利、教育医疗等。

交互建议：
- 桌面端使用 Tab 或分段控制。
- 移动端使用下拉选择 + 卡片列表。
- 每个入口给出“适用对象、核心问题、推荐产品、典型案例”。

### 3.6 技术与交付优势

目标：解释为什么筑云能持续交付，而不是只展示功能清单。

建议表达：
- 自主研发能力
- 工程行业深度适配
- 多引擎与国产化生态适配
- 全生命周期服务
- 案例沉淀与实施方法论

设计建议：
- 使用“能力证据矩阵”，每一项能力对应一个证明材料。
- 技术图使用真实架构图或简化示意，不画空洞节点网络。

### 3.7 精选案例

目标：用真实项目建立行业信任。

首页推荐展示：
- 3-5 个精选案例，最多 6 个。
- 每个案例必须包含行业、客户类型、应用场景、使用能力和成果摘要。
- 客户名称、Logo、项目图片未授权时，使用行业化表达并标注待授权。

布局建议：
- 一个横向重点案例 + 若干小案例。
- 避免所有案例同款三列卡片。
- 支持跳转案例库，案例库再做筛选。

### 3.8 信任背书与转化 CTA

目标：收口信任并推动咨询。

建议内容：
- 客户结构、项目数量、专利软著、奖项资质的二次背书。
- 代表性资质和奖项展示 4-6 个，完整列表进入荣誉资质页。
- CTA 文案统一为“预约咨询”。

设计注意：
- 不做密集证书墙。
- 不堆满合作伙伴 Logo。
- CTA 区域必须有明确联系方式或表单入口。

## 4. 二级页面模块库

### 4.1 产品详情页

推荐模块：
1. 产品 Hero：产品定位、适用对象、核心截图、CTA。
2. 解决问题：3-5 个业务问题。
3. 核心能力：按功能域分组。
4. 应用场景：企业、项目、监管、现场、运维等。
5. 技术架构或产品架构。
6. 相关案例。
7. 相关方案与资源下载。
8. 咨询 CTA。

### 4.2 解决方案详情页

推荐模块：
1. 方案 Hero：客户角色或行业场景定位。
2. 典型问题。
3. 筑云方案路径。
4. 推荐产品组合。
5. 交付成果。
6. 典型案例。
7. 实施流程。
8. 咨询 CTA。

### 4.3 客户案例详情页

推荐模块：
1. 案例 Hero：项目名、行业、客户类型、服务内容。
2. 项目背景。
3. 客户挑战。
4. 筑云方案。
5. 平台能力与交付内容。
6. 成果摘要。
7. 图片或截图组。
8. 相关产品、相关方案、相似案例。

### 4.4 资源详情页

推荐模块：
1. 文章标题与摘要。
2. 标签、日期、内容类型。
3. 正文内容。
4. 关联产品或解决方案。
5. 相关资源推荐。
6. 资料下载或咨询入口。

## 5. 响应式规则

### 桌面端

- 最大内容宽度建议 1200-1440px。
- 首页避免连续使用同一种布局，8 个模块至少使用 4 种结构。
- 重要页面首屏 CTA 必须可见。
- Mega Menu 不超过 3 列，避免成为第二个 Sitemap。

### 平板端

- 二列布局优先收敛为主内容 + 辅助内容。
- 卡片每行 2 个，产品截图可缩小但不能裁掉关键文字。
- 表格类信息改为分组卡片。

### 移动端

- 所有多列模块收敛为单列。
- 首屏顺序为标题、说明、CTA、主视觉、信任数字。
- 信任数字改为 2 列或横向滑动，不挤成 4 列小字。
- 筛选器使用下拉或横向标签，不占满首屏。
- 表单输入框高度和按钮触控区域不低于 44px。

## 6. 动效与交互规则

推荐动效：
- 导航滚动状态切换。
- 按钮 hover 和 active 反馈。
- 模块进入视口时轻微上移和透明度变化。
- Mega Menu 展开收起。
- 案例卡片 hover 显示更多信息。
- Tab 或分段控制切换时的淡入过渡。

不建议：
- 全站强视差。
- 滚动劫持。
- 自动播放的大面积视频背景。
- 复杂粒子、光球、持续旋转的三维背景。
- 用 div 手工搭假的产品截图。

无障碍要求：
- 所有动效支持减少动态效果。
- 键盘可访问导航、菜单、Tab、表单。
- 图片有真实 alt，不堆关键词。
- 表单错误可被屏幕阅读器识别。

## 7. 前端组件命名建议

```text
SiteHeader
MegaMenu
HeroPlatform
ProofMetrics
PainSolutionGrid
CapabilityMap
ProductPlatformCard
SolutionSegmentTabs
CaseFeatureCard
CaseGrid
HonorStrip
ResourceCard
ContactLeadForm
ConversionCTA
SiteFooter
```

组件原则：
- 组件只承载结构与表现，内容来自 CMS 字段。
- 首页模块不要硬编码案例、产品和方案列表。
- 图片组件必须预留宽高，避免布局偏移。
- 产品截图和案例图必须支持替换、裁切焦点和 alt 字段。

## 9. 交付验收标准

- 首页模块数量保持 8 个主模块。
- 顶部导航包含“首页”，桌面端不换行。
- Hero 指标使用客户结构、项目、专利软著和奖项，不使用“2014 年成立”。
- 全站 CTA 文案统一，主 CTA 使用“预约咨询”。
- 真实截图和真实项目图片优先，没有素材时使用明确占位，不生成虚假项目画面。
- 设计稿需提供桌面端和移动端，不能只交桌面视觉。
- 组件状态完整，包括 hover、focus、active、disabled、loading、empty、error。
- 文案、图片、案例、证书和联系方式上线前完成口径复核。
