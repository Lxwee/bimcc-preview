版本：2026-09-01  
用途：首页 8 个模块的版式、信息密度、素材位置、交互方式与移动端适配说明

## 1. 页面整体原则

首页采用“平台可信 + 工程场景 + 清晰转化”的结构，不做长宣传册式堆叠。

设计目标：
- 首屏建立公司定位、技术底座和信任指标。
- 中段完成产品、方案、技术、案例的分流。
- 尾部用资质、合作伙伴和 CTA 完成转化。

信息密度：
- 桌面端允许中高信息密度，但每屏只讲一个核心问题。
- 移动端优先保留标题、关键句、主 CTA 和 2-4 个关键卡片，其余使用折叠、横滑或跳转二级页。

推荐页面节奏：

```text
强识别首屏 -> 问题共鸣 -> 能力体系 -> 产品入口 -> 方案分流 -> 技术证明 -> 案例信任 -> CTA 收口
```

## 2. 模块 1：首屏 Hero + 核心数字背书

### 桌面端版式

结构：
- 顶部：Logo + 首页 + 产品平台 + 解决方案 + 客户案例 + 技术与研发 + 资源中心 + 关于筑云 + 联系我们 + 预约咨询按钮
- 主区左侧：定位标签、主标题、副标题、说明文案、双 CTA
- 主区右侧：平台驾驶舱 / BIM+GIS 一张图 / 数字孪生大屏主视觉
- 底部：4 个横向核心数字

推荐比例：
- 左侧文案 45%
- 右侧主视觉 55%
- 指标区横跨全屏内容宽度

指标：

```text
80% 大型国央企 / 政府监管客户
1000+ 重点建设项目
80+ 专利软著
100+ 国家级、省部级奖项
```

视觉重点：
- 主视觉不要用纯抽象科技背景。
- 右侧画面要体现“项目一张图、平台管理、数字孪生或驾驶舱”。
- 指标需要高对比、易扫读，不要做成小字脚注。

### 移动端版式

结构：
- Logo + 首页入口 + 菜单 + 预约咨询
- 标题优先，主视觉下移
- CTA 保留 1 个主按钮 + 1 个文字链接
- 指标改成两列或横向滑动

## 3. 模块 2：客户痛点 + 筑云解法

### 桌面端版式

推荐：左右对照或 2x3 卡片。

方案 A：左右对照
- 左侧：客户痛点
- 右侧：筑云解法
- 适合表达“系统割裂 -> 统一平台”的因果关系

方案 B：2x3 卡片
- 每张卡片上半部是痛点，下半部是解法
- 适合响应式和后续 CMS 配置

推荐采用方案 B，更容易落地。

### 内容密度

每张卡片控制在：
- 痛点标题：12 字以内
- 解法说明：35-55 字

### 交互建议

- 桌面端 Hover 时突出“解法”。
- 移动端默认完整展示，不依赖 Hover。

## 4. 模块 3：一体化能力地图

### 桌面端版式

推荐使用三层架构图：

```text
飞椽 Fyra 智能开发平台
    ↓
BIMCC 智能建造平台
    ↓
智慧工地 / BIM 咨询 / 数字孪生 / 展厅指挥中心 / 数字教育 / 工程创新技术
```

左侧可以放一段解释，右侧放架构图；或整屏居中展示一张横向架构图。

### 视觉要求

- 三层之间要有明确上下游关系，不要做成 8 个同级业务卡片。
- 飞椽是底座，BIMCC 是平台，全生命周期服务是交付层。
- 用不同层级色块或线条表达能力流动。

### 移动端

三层架构改成纵向堆叠，层与层之间用箭头或连接线。

## 5. 模块 4：核心产品平台

### 桌面端版式

推荐 3x2 卡片网格。

每张卡片结构：

```text
产品名称
一句话定位
2-3 个关键词
简短说明
按钮
```

推荐卡片：
- 飞椽 Fyra 智能开发平台
- BIMCC 智能建造平台
- 智慧工地建设
- 数字孪生与智慧运维
- BIM 咨询服务
- 数字化教育体系

### 视觉处理

- 每张卡片搭配一个小型产品截图、图标或线性示意图。
- 飞椽和 BIMCC 平台应比其他卡片更突出，可做成前两张重点卡。
- 卡片不宜过度玻璃拟态，工程客户更重视清晰与可信。

### 移动端

采用单列卡片，飞椽和 BIMCC 平台优先展示，其余可折叠或横滑。

## 6. 模块 5：解决方案入口

### 桌面端版式

推荐采用双 Tab：

```text
按客户角色 / 按行业场景
```

Tab 内使用 3 列卡片，每张卡片包含：
- 名称
- 典型挑战
- 推荐方案组合
- 相关案例入口

### 为什么合并为一个模块

客户既可能按“我是谁”找方案，也可能按“我是什么行业”找方案。两个模块分开会拉长首页；合并为 Tab 既保留完整入口，又控制页面长度。

### 移动端

- Tab 保留。
- 卡片单列。
- 行业场景可以横滑标签 + 卡片详情。

## 7. 模块 6：技术与交付优势

### 桌面端版式

推荐“左侧技术主张 + 右侧 6 个优势点”。

也可做成横向时间/能力链路：

```text
数据接入 -> 模型融合 -> 业务协同 -> AI 预警 -> 平台交付 -> 运维沉淀
```

### 重点

技术表达必须转译成客户价值：
- 多引擎不是为了炫技，而是为了融合模型、地图、实景和业务数据。
- 零代码不是为了概念，而是为了缩短交付周期、降低重复开发成本。
- AI 不是泛泛说智能，而是用于安全管理、文档查询、数据分析和平台操作。

### 移动端

建议使用图标列表，不做复杂横向链路。

## 8. 模块 7：精选案例

### 桌面端版式

推荐：
- 顶部：标题 + 副标题 + 行业筛选标签
- 中部：2x3 或 4x2 案例卡片
- 底部：查看全部客户案例 CTA

案例卡片字段：

```text
项目名称
行业 / 客户类型
使用产品或服务
解决的问题
交付成果
```

### 案例筛选标签

首页建议只放 5-6 个标签：
- 企业级平台
- 民航机场
- 轨道交通
- 水利水电
- 医疗教育
- 数字孪生

### 移动端

案例卡片建议横滑或单列，不在首页展示太多项目图。

---

## 9. 模块 8：信任背书 + 转化 CTA

### 桌面端版式

推荐分成上下两段：

第一段：信任背书
- 企业资质
- 技术资产
- 行业荣誉
- 合作生态

第二段：转化 CTA
- 标题
- 说明
- 表单入口 / 电话 / 微信 / 资料下载

### 视觉处理

- 荣誉资质只展示代表性，不做完整证书墙。
- 合作伙伴 Logo 分组展示，数量控制。
- CTA 区要比普通模块更明确，可以使用深色背景或高对比按钮。

### 移动端

信任背书压缩成 4 个折叠项，CTA 固定为“预约方案咨询”。

## 11. 设计落地注意事项

1. 首页不要做成“宣传册搬家”，每屏只解决一个访客判断问题。
2. 首屏必须有强主视觉，且优先使用真实平台或项目资产。
3. 产品卡片要突出飞椽 Fyra 与 BIMCC 智能建造平台的底座地位。
4. 解决方案模块要完成分流，不要把所有行业长篇说明塞进首页。
5. 案例模块要精选代表性，不追求数量。
6. 信任背书要克制，避免证书墙和 Logo 墙挤压转化 CTA。
