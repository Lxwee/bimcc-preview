## 4. 参考筛选标准

适合筑云官网的参考应具备：

- 首屏能在几秒内说明定位。
- 有真实平台、真实项目或真实产品证据。
- 适合政企和工程客户阅读。
- 导航清楚，CTA 明确。
- 案例模块可信，不像模板堆图。
- 科技感服务于理解，不靠光效撑场面。
- 移动端能压缩而不丢重点。

不适合作为主参考：

- 只有抽象渐变和科技背景。
- 没有真实业务内容。
- 首页模块过多且优先级混乱。
- 全站都是三列卡片。
- 动效复杂但不能帮助理解。
- 政企客户看起来不稳重。

---

## 5. 高保真视觉判断维度

收到参考和素材后，建议从 10 个维度判断：

| 维度 | 判断问题 |
|---|---|
| 首屏识别 | 是否一眼看出筑云是工程数字化平台公司 |
| 平台可信 | 是否能展示真实平台能力 |
| 工程现场感 | 是否能体现项目和现场 |
| 研发底座 | 是否能讲清飞椽 Fyra 和自研能力 |
| 信息密度 | 是否适合政企决策客户扫描 |
| 模块节奏 | 首页 8 模块是否有起伏 |
| 案例说服力 | 是否证明做过而不是只说能做 |
| 转化清晰度 | 是否能自然引导预约咨询 |
| 响应式 | 移动端是否保持重点 |
| 品牌辨识 | 是否不像通用科技模板 |

## 6. 首页高保真出稿范围

第一轮高保真建议只做：

```text
首页桌面端完整稿
首页移动端关键稿
Header / Footer
核心组件状态
```

暂不建议同时做所有二级页高保真。原因：

- 首页定调后，二级页可以继承系统。
- 素材和内容还需要复核。
- 如果首页视觉方向调整，二级页会重复返工。

---

## 7. 高保真前不能跳过的确认

进入高保真前确认：

- 首页仍保持 8 个主模块。
- 顶部导航包含“首页”。
- Hero 指标不使用“2014 年成立”。
- 80%、1000+、80+、100+ 四类指标已确认展示口径或保留待复核标识。
- 预约咨询是主 CTA。
- 可公开案例名单已确认或用脱敏表达。
- 产品截图可以公开或使用占位。
- 联系方式已复核或保持待复核。

---

## 8. 给设计师的方向边界

默认方向：

```text
平台驾驶舱型为主，工程现场型与研发底座型辅助。
```

设计应避免：

- 过度深蓝，整站像模板科技公司。
- 过度政府门户，信息过密。
- 过度 SaaS，缺少工程项目可信度。
- 过度炫技，影响阅读和移动端性能。
- 用抽象图形替代真实平台和案例。

设计应强化：

- 平台截图的真实感。
- 工程项目的可信度。
- 自研技术底座。
- 政企客户可接受的稳重感。
- 页面模块之间的节奏变化。

---

## 9. 给前端的方向边界

高保真视觉稿确认后，前端实现需保留：

- 统一设计 token。
- 单一主色和稳定中性色。
- 清楚的组件状态。
- 响应式断点。
- 图片尺寸和占位规则。
- 无障碍基础状态。
- 动效降级方案。

前端不应自行发明：

- 新的主色。
- 新的字体方向。
- 未确认的客户 Logo。
- 未确认的项目图片。
- 未确认的统计数字。
- 复杂滚动效果。
