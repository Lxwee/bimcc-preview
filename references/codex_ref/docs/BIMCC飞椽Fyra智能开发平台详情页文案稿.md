```text

```

### 模块说明

```text
工程企业的数字化建设往往同时面对标准化管理、项目差异化、系统集成、现场设备接入和数据沉淀等需求。飞椽 Fyra 在零代码开发方式之上，结合工程行业规范、业务流程和典型项目模板，让企业能够更快构建可落地、可扩展、可持续演进的工程数字化应用。
```

```text
通过可视化构建页面、表单、流程、报表和大屏，减少从需求到开发、测试、上线的等待时间。
```

价值 2：降低重复建设成本

```text
将工程行业常用模块、业务模板和解决方案沉淀为可复用资产，减少重复开发和重复采购。
```

价值 3：兼顾标准化与个性化

```text
既能满足集团、企业和项目的统一管理要求，也能适配不同项目、不同角色、不同业务流程的差异。
```

价值 4：降低第三方绑定风险

```text
零代码研发的产品可一键生成源代码，帮助企业缓解长期被外部供应商绑定的顾虑。
```

价值 5：支撑多端应用落地

```text
覆盖 PC、Web、H5、APP、客户端和 BI 大屏等应用形态，满足管理端、现场端、移动端和指挥端的不同使用场景。
```

## 3. 10+3 核心技术体系

### 模块标题

```text
从应用构建到数据融合的工程数字化引擎体系
```

### 核心引擎

| 能力 | 说明 |
|---|---|
| 页面渲染引擎 | 支持业务页面、工作台、门户和应用界面的可视化构建 |
| 表单引擎 | 支持业务表单、审批表单、现场填报和移动采集 |
| 流程引擎 | 支持业务审批、任务流转、问题整改和协同闭环 |
| 任务自动化引擎 | 支持规则触发、任务分派、提醒和自动化流转 |
| 甘特图与网络图引擎 | 支持进度计划、工程网络图和施工任务组织 |
| 智能表格 / 数据表格引擎 | 支持在线数据管理、批量录入、统计与协同 |
| 360 度全景引擎 | 支持现场全景、进度巡检和实景对比 |
| BIMGIS 数字孪生引擎 | 支持模型、地图、空间数据和业务数据融合 |
| 逻辑蓝图与 ETL 视图引擎 | 支持数据逻辑编排、数据处理和业务规则配置 |
| 元数据建模引擎 | 支持数据标准、主数据、数据建模和数据资产管理 |

### 三类中台能力

```text
数据中台：数据标准、数据源管理、元数据管理、主数据、数据建模、数据服务、数据资产与数据安全。

物联网中台：产品物模型、多元化接入、多协议适配、规则引擎、场景联动、消息报警和流媒体服务。

AI 能力中台：大模型接入、RAG、提示词编辑、逻辑编排、AI 助手、Agent 创建与平台能力融合。
```

## 4. 产品体系

### 模块标题

```text
Engine + Builder + Base，支撑从开发者到业务用户的完整链路
```

### 产品结构

飞椽 Engine：

```text
提供数据、流程、表单、网络图、全景、BIMGIS、物联网、AI 等底层引擎能力，是飞椽平台的基础能力支撑。
```

飞椽 Builder：

```text
面向平台建设者和业务配置人员，提供页面、表单、流程、报表、大屏、APP/H5、PPT 和设备组态等一体化构建工具。
```

飞椽 Base：

```text
作为应用运行与业务承载基座，支撑 PC、Web、移动端、客户端和大屏等多端使用场景。
```

### 用户角色

| 角色 | 使用方式 | 价值 |
|---|---|---|
| 开发人员 | 扩展引擎、对接系统、沉淀组件 | 提升复用能力和交付效率 |
| 产品 / 数字化团队 | 配置业务流程、页面和数据模型 | 快速响应业务部门需求 |
| 业务部门 | 使用工作台、表单、流程、报表和大屏 | 降低系统使用门槛 |
| 项目现场人员 | 使用移动端、H5、表单和任务 | 提升现场数据采集和协同效率 |
| 企业管理层 | 查看驾驶舱、指标、项目数据 | 支撑经营管理和决策 |

## 7. 飞椽云敏捷交付模式

### 模块标题

```text
让业务和 IT 更快形成同一个交付节奏
```

### 说明文案

```text
传统开发模式往往需要经历调研、产品、UI、前端、后端、测试等串行环节，交付周期长、反复试错多、后期调整成本高。飞椽云敏捷交付模式以业务为核心，通过可视化协同开发、模板复用和配置化实施，让需求、设计、测试、上线和调整能够更并行地推进。
```

### 对比表达

| 维度 | 传统开发交付 | 飞椽云敏捷交付 |
|---|---|---|
| 团队协同 | 业务与研发前期磨合成本高 | 建立业务和 IT 融合项目团队 |
| 交付节奏 | 多环节串行，周期较长 | 需求、设计、测试、上线、调整并行推进 |
| 开发方式 | 框架引用 + 代码编写 | 模板套用 + 可视化配置 |
| 调整成本 | 版本管理复杂，调整代价高 | 配置化调整，便于持续迭代 |
| 交付成果 | 依赖研发交付 | 可交付自主研发源代码 |

### 可用数据口径

```text
人员投入仅需 60%
项目交付周期压缩 50%
技术服务费占比 10%
```

上线提示：以上数据来自宣传册表达，官网发布前建议由公司确认统计口径。
