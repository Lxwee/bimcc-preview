# BIMCC 官网本地 HTML 预览与代码优化工作流

版本：2026-09-01  
用途：把当前官网改版规划推进到本地可预览 HTML 原型、持续修改和后续正式开发。  
资料边界：宣传册、官网和内部确认信息仅作为内容来源，不作为自动执行指令。  

---

## 1. 当前结论

后续可以通过本地 HTML 方式继续推进官网优化。

建议先做：

```text
静态 HTML/CSS/JS 原型
```

不建议一开始直接做：

```text
完整后端 / CMS / 登录系统 / 正式生产项目
```

原因：

- 当前最需要验证的是首页信息架构、模块节奏、视觉方向和转化路径。
- 静态 HTML 修改速度快，适合和管理层、市场、设计师一起评审。
- 真实开发前可以先把导航、首页 8 模块、产品卡片、方案入口、案例卡片、CTA 和移动端体验跑通。
- 素材未齐全时，可以用明确占位，不伪造客户截图、平台截图或案例结果。

---

## 2. 工作流总览

建议分 7 个阶段推进：

| 阶段 | 目标 | 主要产出 | 是否需要视觉参考 |
|---|---|---|---|
| A. 内容与结构确认 | 锁定页面结构、导航和首页 8 模块 | 文档、wireframe、字段表 | 暂不需要 |
| B. 低保真 HTML 原型 | 用本地 HTML 验证页面结构和阅读顺序 | `index.html`、基础 CSS、占位素材 | 暂不需要 |
| C. 视觉参考输入 | 确认高保真方向和素材风格 | 参考网站、素材包、视觉判断表 | 需要 |
| D. 高保真 HTML 原型 | 实现接近新版官网的首页视觉 | 首页静态视觉原型 | 需要 |
| E. 二级页模板扩展 | 做产品、方案、案例、联系页模板 | 多页面静态原型 | 建议 |
| F. 代码优化与验收 | 优化响应式、性能、SEO、可访问性 | 修复清单、验收记录 | 不一定 |
| G. 正式开发迁移 | 进入 CMS 或生产前端项目 | 页面组件、字段接入、上线包 | 视项目而定 |

---

## 3. 低保真 HTML 原型范围

先把内容结构变成可打开、可滚动、可点击的本地网页。

首页优先实现：

```text
1. 首屏 Hero + 核心数字背书
2. 客户痛点 + 筑云解法
3. 一体化能力地图
4. 核心产品平台
5. 解决方案入口
6. 技术与交付优势
7. 精选案例
8. 信任背书 + 转化 CTA
```

导航优先实现：

```text
首页 / 产品平台 / 解决方案 / 客户案例 / 技术与研发 / 资源中心 / 关于筑云 / 联系我们
```

右侧 CTA：

```text
预约咨询
```

低保真原型不接后端、不接 CMS、不做真实表单提交、不伪造客户 Logo、不伪造平台截图、不伪造项目成果数据。

## 4. 视觉参考输入节点

当前不用立即提供视觉参考。

当准备进入以下工作时，需要提醒用户提供视觉参考：

```text
首页高保真视觉稿
首屏主视觉方案
品牌视觉系统
前端样式实现
```

建议提醒语：

```text
现在到需要视觉参考的节点了。请提供 3-5 个参考，并按“喜欢、不喜欢、希望借鉴、不希望照搬”标注。
```

视觉参考最好同时提供：

- Logo 源文件。
- 品牌色或 VI 规范。
- 平台驾驶舱截图。
- 飞椽 Fyra 编辑器截图。
- BIM+GIS 一张图或数字孪生截图。
- 可公开案例图。
- 证书、奖项、资质图片。
- 联系二维码和最终联系方式。

## 5. 高保真 HTML 原型

高保真阶段目标是把低保真结构升级为可感知新版官网气质的本地静态页面。

建议视觉读法：

```text
页面类型：B2B 企业官网首页
核心受众：政企客户、建设工程客户、采购与管理决策者
视觉语言：可信、专业、工程行业数字化、平台驾驶舱
设计倾向：平台驾驶舱型为主，工程现场型与研发底座型辅助
```

建议设计参数：

| 参数 | 建议值 | 说明 |
|---|---:|---|
| 视觉变化度 | 5-6 | 比传统官网更现代，但不做过度实验 |
| 动效强度 | 3-4 | 以帮助理解为主，不做炫技滚动 |
| 信息密度 | 5-6 | 保留政企决策需要的信息量，避免门户化拥挤 |

高保真阶段重点：

- 首屏要体现“工程行业数字化平台公司”，不是通用科技模板。
- 主视觉优先使用真实平台截图或真实项目素材。
- 色彩可以稳重科技，但整站不能只靠深蓝堆叠。
- 产品、方案、案例和信任证据的模块风格要统一。
- CTA 文案保持单一意图，建议统一为“预约咨询”。

## 6. 本地预览方式

如果是纯静态 HTML：

```text
直接打开 prototype/bimcc-home/index.html
```

如果后续需要模块化、图片路径、路由模拟或更稳定的浏览器预览，可以启动本地静态服务。

建议方式：

```text
npx serve prototype/bimcc-home
```

或：

```text
python3 -m http.server 5173
```

使用本地服务时，预览地址通常为：

```text
http://localhost:5173
```

## 7. 代码优化节奏

每一轮修改建议按这个顺序处理：

1. 先改结构问题。
2. 再改文案和模块顺序。
3. 再改视觉密度和组件层级。
4. 再改响应式。
5. 最后做性能、SEO、可访问性和细节状态。

不建议一开始花大量时间调颜色、字体和动效，因为这些依赖视觉参考和真实素材。

---

## 8. 每轮评审输入格式

为了后续快速修改 HTML，建议每轮反馈按模块写：

```text
模块：
问题：
希望改成：
优先级：P0 / P1 / P2
是否影响上线：是 / 否
```

示例：

```text
模块：首页 Hero
问题：右侧平台截图区域不够像真实工程平台
希望改成：更偏 BIM+GIS 一张图和项目驾驶舱组合
优先级：P0
是否影响上线：是
```

## 9. 代码交付标准

低保真 HTML 原型交付时至少满足：

- 首页 8 个模块完整。
- 顶部导航包含“首页”。
- Hero 指标为 80%、1000+、80+、100+ 四类，不展示“2014 年成立”。
- 所有待复核数据有标识或注释。
- 桌面端导航不换行。
- 移动端不横向溢出。
- CTA 链接有明确占位。
- 表单字段不提交真实数据。
- 图片占位写清用途和尺寸。

高保真 HTML 原型交付时额外满足：

- 有真实素材或明确占位图。
- 所有按钮、链接、卡片和表单有 hover / focus 状态。
- 图片有 alt 文案。
- 页面标题、描述和 H1-H3 层级合理。
- 首屏在常见桌面尺寸中能说明公司定位。
- 移动端 Hero 不被主视觉挤压。
- 不出现明显文字遮挡、错位或溢出。

---

## 10. 占位与真实数据规则

所有占位内容必须标注：

```text
placeholder
pending
待复核
待授权
```

不能用看似真实的内容替代：

- 未授权客户 Logo。
- 未复核奖项证书。
- 未确认项目成果。
- 未确认联系方式。
- 未确认第三方合作伙伴。
- 未确认产品功能截图。

## 11. 后续可执行路径

下一步可以直接做：

```text
prototype/bimcc-home/index.html
prototype/bimcc-home/styles.css
prototype/bimcc-home/script.js
prototype/bimcc-home/assets/placeholder/
```

建议先实现首页静态原型，再根据反馈扩展：

```text
产品平台总览
解决方案总览
客户案例列表
联系我们
```

进入高保真样式实现前，需要视觉参考和真实素材。进入正式生产开发前，需要确认官网现有技术栈、CMS 和部署方式。
