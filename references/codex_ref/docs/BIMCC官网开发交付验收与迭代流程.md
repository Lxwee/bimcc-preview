# BIMCC 官网开发交付验收与迭代流程

版本：2026-09-01  
用途：定义从本地 HTML 原型到正式开发、内容迁移、上线验收和后续迭代的协作流程。  

---

## 1. 总体流程

建议采用以下流程：

```text
内容确认
低保真 HTML 原型
视觉参考输入
高保真视觉原型
核心页面开发
CMS / 内容接入
联调与验收
上线
上线后迭代
```

当前可以进入：

```text
低保真 HTML 原型
```

进入高保真视觉原型前，需要视觉参考和真实素材。

---

## 2. 角色分工

| 角色 | 责任 |
|---|---|
| 项目负责人 | 确认范围、优先级、上线节奏 |
| 市场 / 品牌负责人 | 确认文案、案例、视觉方向和对外口径 |
| 产品 / 业务负责人 | 确认产品能力、方案场景和功能边界 |
| 设计负责人 | 输出视觉稿、组件规范和素材处理方式 |
| 前端负责人 | 实现页面、交互、响应式和性能优化 |
| CMS / 后台负责人 | 配置字段、内容模型和数据关系 |
| 内容运营 | 迁移新闻、案例、资源和荣誉资料 |
| 审核人 | 复核数据、联系方式、授权和上线风险 |

---

## 3. 迭代节奏

建议按小步快跑方式：

| 轮次 | 目标 | 输出 |
|---|---|---|
| 第 1 轮 | 首页低保真 HTML | 验证模块顺序、文案长度、导航和移动端 |
| 第 2 轮 | 首页高保真视觉 | 确认视觉方向、素材风格、组件状态 |
| 第 3 轮 | P0 二级页模板 | 产品、方案、案例、联系页模板 |
| 第 4 轮 | CMS 数据接入 | 字段映射、内容录入、图片管理 |
| 第 5 轮 | 上线验收 | SEO、性能、表单、链接、移动端 |

每轮建议只处理一个主要目标，避免“边改结构、边改视觉、边改技术栈”导致返工。

---

## 4. 问题记录格式

建议用统一格式记录问题：

```text
编号：
页面：
模块：
问题描述：
修改建议：
优先级：P0 / P1 / P2
负责人：
状态：todo / doing / review / fixed / deferred
是否阻塞上线：是 / 否
```

状态说明：

| 状态 | 含义 |
|---|---|
| todo | 已确认待处理 |
| doing | 正在处理 |
| review | 已修改，等待复核 |
| fixed | 已复核通过 |
| deferred | 本轮不处理，进入后续迭代 |

## 7. 开发验收清单

页面结构：

- 顶部导航包含“首页”。
- 首页保持 8 个主模块。
- 页脚包含核心联系方式和导航。
- 产品、方案、案例、联系页之间可互相跳转。
- P0 页面没有空白主模块。

内容：

- Hero 不使用“2014 年成立”作为核心指标。
- “2014 年成立”只出现在关于页、发展历程或页脚辅助信息。
- 80%、1000+、80+、100+ 的口径有状态标识。
- 客户名称和 Logo 授权状态清楚。
- 联系方式待复核内容不误发布。

交互：

- 桌面端导航不换行。
- 移动端菜单可展开和关闭。
- CTA 链接有效。
- 表单字段有 label。
- 表单提交有成功、失败或占位反馈。
- 案例筛选或分类状态清楚。

视觉：

- 首屏能说明公司定位。
- 卡片、按钮、标签、表单和页脚风格统一。
- 不连续堆叠相同布局。
- 首页 8 模块至少有 4 种布局类型。
- 真实图片或占位图片比例稳定。

响应式：

- 390px 移动宽度无横向溢出。
- 768px 平板宽度布局可读。
- 1280px 桌面宽度导航一行显示。
- 1440px 桌面宽度首屏留白合理。

SEO：

- 每个页面有唯一 title。
- 每个页面有 meta description。
- 每个页面只有一个 H1。
- H2-H3 层级合理。
- 图片 alt 使用真实描述。
- 不堆关键词。

性能：

- 首页首屏图片压缩。
- 非首屏图片懒加载。
- CSS 和 JS 不过度膨胀。
- 动效不影响滚动和输入。
- 页面打开无明显闪烁和布局跳动。

## 8. 本地原型验收

本地 HTML 原型验收重点：

- 能直接打开或通过本地服务打开。
- 首页 8 模块顺序正确。
- 文案和现有文档一致。
- 所有 placeholder 有清楚说明。
- 待复核 / 待授权信息没有被当作正式内容。
- 移动端可浏览。
- 反馈修改能快速落到代码。

不要求：

- 接 CMS。
- 真实表单提交。
- 完整 SEO 路由。
- 最终生产性能。
- 所有二级页完整。

---

## 9. 正式上线验收

正式上线前需要额外完成：

- URL 迁移和重定向。
- 旧页面保留、合并或下线规则。
- 备案、隐私政策和表单合规文案。
- 站点地图。
- robots 配置。
- 404 页面。
- OG 分享图。
- 百度、搜索引擎和统计代码。
- 表单接收和线索分配。
- 图片压缩和 CDN。
- 备份和回滚方案。

---

## 10. 风险与处理

| 风险 | 影响 | 处理方式 |
|---|---|---|
| 视觉参考不足 | 高保真方向反复 | 高保真前提醒用户补 3-5 个参考 |
| 平台截图不足 | 首屏缺少真实感 | 低保真阶段用明确占位，高保真前必须补 |
| 客户授权不足 | 案例可信度下降 | 使用脱敏表达或行业化案例 |
| 数据口径未复核 | 上线风险 | 所有数字保留 pending 状态 |
| 联系方式未复核 | 转化链路错误 | 联系页和 Footer 上线前专项核对 |
| 页面范围过大 | 交付延期 | P0 先上线核心闭环，P1 后续扩展 |
| CMS 字段不稳定 | 开发返工 | 先按字段模型做样例数据评审 |

---

## 11. 后续迭代机制

上线后建议按月或季度评估：

- 首页转化点击。
- 预约咨询表单数量。
- 产品页访问深度。
- 解决方案入口点击比例。
- 案例页访问和停留。
- 资源中心搜索流量。
- 移动端访问占比和跳出率。

根据数据调整：

- 首页案例排序。
- 产品平台入口权重。
- 解决方案分类。
- CTA 文案和位置。
- 资源中心内容选题。
- SEO 页面优先级。
