# BIMCC 官网视觉参考需求清单

版本：2026-09-01  
用途：明确什么时候需要用户提供视觉参考、需要提供哪些参考、如何判断参考是否适合筑云官网改版。  
适用范围：首页高保真视觉稿、视觉系统定稿、首屏主视觉、前端样式实现和后续二级页模板。

---

## 1. 当前结论

当前阶段还不需要马上提供视觉参考。

已经可以继续推进的内容：
- 首页页面级 wireframe。
- 第一批上线页面路由与开发任务拆分。
- CMS 字段模型和样例数据。
- 素材采集清单。
- SEO 与上线验收。
- 管理层评审版内容包。

必须提醒用户提供视觉参考的节点：

```text
进入首页高保真视觉稿前
确认品牌视觉系统前
确认首屏主视觉方向前
进入前端样式实现前
```

换句话说，现在可以继续把结构、文案、字段、路由和任务拆细。下一阶段如果要开始“真正长得像新版官网”的视觉稿，就需要参考。

---

## 2. 为什么需要视觉参考

视觉参考不是为了照搬其他网站，而是为了减少以下风险：

- 过度蓝色科技风，看起来像通用模板。
- 过度政府门户风，显得传统和信息拥挤。
- 过度 SaaS 风，缺少工程现场和项目可信度。
- 过度炫技，政企客户难以快速理解。
- 设计师对“平台驾驶舱型”的理解不一致。
- 首屏主视觉不确定，导致反复调整。

筑云官网更适合的基调：

```text
平台驾驶舱型为主
工程现场型辅助
研发底座型补强
整体稳重、清晰、可信、有真实项目感
```

---

## 3. 最佳提供时点

### 当前阶段：不用提供

当前正在完成：
- 内容规划。
- 页面结构。
- wireframe。
- CMS 数据结构。
- 开发任务拆分。

这些工作依赖业务和信息架构，不强依赖视觉参考。

### 下一阶段：建议提供

当准备进入以下工作时，请提供视觉参考：

| 即将开始的工作 | 是否需要参考 | 原因 |
|---|---|---|
| 首页高保真视觉稿 | 必需 | 决定首屏气质、配色、字体、版式和素材风格 |
| 首屏主视觉方案 | 必需 | 决定平台截图、工程现场图、数字孪生图的组合方式 |
| 组件视觉系统 | 必需 | 决定按钮、卡片、标签、表单、导航和 Mega Menu 样式 |
| 二级页视觉模板 | 建议 | 保证产品页、方案页、案例页和首页风格一致 |
| 前端样式实现 | 必需 | 开发需要明确 token、断点、组件状态和交互动效 |

## 4. 参考数量建议

建议提供 3-5 个参考，不需要太多。

推荐组合：

| 类型 | 数量 | 作用 |
|---|---:|---|
| 整站风格参考 | 1-2 个 | 判断整体气质 |
| 首屏或 Hero 参考 | 1-2 个 | 判断第一屏构图 |
| 产品平台或驾驶舱参考 | 1-2 个 | 判断截图展示方式 |
| 案例或行业页面参考 | 1 个 | 判断案例卡片和项目表达 |
| 不喜欢的反例 | 1-2 个 | 避免走偏 |

最少也可以只给：

```text
1 个喜欢的官网
1 个不喜欢的官网
3 张公司真实素材
```

---

## 5. 每个参考怎么标注

请按这个模板提供：

```text
参考 1：
链接或截图：
喜欢的地方：
不喜欢的地方：
希望借鉴到筑云官网的部分：
不希望照搬的部分：
适合页面：首页 / 产品页 / 方案页 / 案例页 / 联系页
```

示例：

```text
参考 1：
链接或截图：某智能建造平台官网
喜欢的地方：首页首屏平台截图很真实，导航清晰，CTA 明确。
不喜欢的地方：整站太蓝，案例模块有点像模板。
希望借鉴到筑云官网的部分：首屏截图展示方式和产品卡片层级。
不希望照搬的部分：深蓝背景和三列卡片重复。
适合页面：首页、产品页。
```

## 6. 公司素材同步提供

视觉参考最好和公司真实素材一起给，效果会更准。

### P0

- Logo 源文件，包括深色版、浅色版和标准版。
- 品牌色或 VI 规范。
- BIMCC 智能建造平台驾驶舱截图。
- 飞椽 Fyra 编辑器截图。
- BIM+GIS 一张图或数字孪生大屏截图。
- 5-6 张可公开案例封面图。
- 代表性证书、奖项或资质图片。
- 联系二维码和最终联系方式。

### P1

- 智慧工地现场图。
- 指挥中心或展厅照片。
- BIM 咨询成果图。
- 无人机、三维扫描、BIMVR、3DGS 等专项技术图。
- 合作伙伴 Logo。
- 产品手册或解决方案 PDF。

## 7. 参考筛选标准

适合筑云的参考：
- 有真实产品截图或真实项目场景。
- 首屏信息清晰，能快速说明定位。
- 导航克制，栏目结构清楚。
- 案例和客户证据可信。
- 页面有科技感，但不靠光效堆砌。
- B2B 决策客户看起来不浮夸。

不适合作为主参考：
- 只有抽象渐变和光效，没有真实内容。
- 所有模块都是三列卡片。
- 首页太长，信息没有优先级。
- 导航复杂到像门户网站。
- 首屏只有口号，缺少产品或项目证据。
- 大量使用无法落地的炫酷滚动效果。

---

## 8. 视觉方向判断表

收到参考后，建议按以下维度判断：

| 维度 | 要判断的问题 |
|---|---|
| 首屏气质 | 是平台公司、工程公司，还是通用科技公司 |
| 主视觉 | 是真实平台、真实项目，还是抽象背景 |
| 信息密度 | 是否适合政企和工程客户快速扫描 |
| 产品展示 | 是否能讲清飞椽和 BIMCC 的关系 |
| 解决方案 | 是否能完成客户角色分流 |
| 案例表达 | 是否证明做过，而不是只摆图片 |
| 颜色 | 是否过度蓝色、过度渐变或过度暗色 |
| 动效 | 是否为理解服务，而不是为了炫技 |
| 移动端 | 是否能压缩而不丢信息 |

## 9. 我会在这些节点提醒

我会在以下情况明确提醒你提供视觉参考：

1. 准备进入首页高保真视觉稿时。
2. 准备确定首屏主视觉方案时。
3. 准备确定品牌色、字体、圆角、图标和组件风格时。
4. 准备让前端按视觉稿实现样式时。
5. 发现现有方向可能与管理层审美或品牌资产冲突时。

提醒语会直接说明：

```text
现在到需要视觉参考的节点了。请提供 3-5 个参考，并按“喜欢、不喜欢、希望借鉴、不希望照搬”标注。
```

---

## 10. 如果暂时没有参考

如果暂时没有视觉参考，可以继续按默认方向推进：

```text
平台驾驶舱型为主
工程现场型辅助
研发底座型补强
色彩稳重，信息清晰，真实素材优先
```

此默认方向适合继续完成：
- 首页 wireframe。
- 页面路由。
- CMS 建模。
- 内容迁移。
- 首批开发任务。
- 素材采集。

但不建议在没有参考和真实素材的情况下直接定稿高保真首页视觉。

当前不用急着提供视觉参考。等准备进入高保真首页视觉稿前，再提供 3-5 个参考最有效；届时我会提醒。
