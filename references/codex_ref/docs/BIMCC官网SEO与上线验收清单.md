## 3. URL 与重定向

### URL 建议

若旧官网 URL 已有搜索权重，优先保留旧 URL 或配置 301 重定向。新 URL 建议简洁稳定：

```text
/
/products
/products/fyra
/products/bimcc-platform
/solutions
/solutions/enterprise-digital-operation
/solutions/project-smart-construction
/cases
/cases/{case-slug}
/contact
/about
/research
/resources
```

### 重定向要求

- 旧官网重点页面必须盘点并映射到新版页面。
- 删除或合并的旧页面配置 301，不直接 404。
- 宣传册或旧物料中已有链接需尽量保留。
- 不确定是否保留的页面先标注待确认，不在上线前临时删除。

## 5. 内容验收

### 首页

- 首页保持 8 个主模块。
- 顶部导航包含“首页”。
- Hero 指标使用 `80% 大型国央企 / 政府监管客户`、`1000+ 重点建设项目`、`80+ 专利软著`、`100+ 国家级、省部级奖项`，最终口径上线前复核。
- “2014 年成立”放入关于筑云或发展历程，不放在 Hero 核心数字位。
- 首屏标题、说明、CTA 在桌面和移动端均可见。
- 预约咨询、查看案例等 CTA 链接有效。

### 产品页

- 每个产品页有清晰的一句话定位。
- 核心能力按业务域分组，不直接堆功能清单。
- 产品截图真实、清晰、已脱敏。
- 产品页能跳转相关方案和案例。
- 飞椽 Fyra、BIMCC 智能建造平台作为 P0 页面优先完整。

### 解决方案页

- 每个方案明确适用对象和核心问题。
- 推荐产品组合要能回链到产品页。
- 交付成果不虚构量化收益。
- 行业和客户角色标签统一。
- 总览页按角色、层级、行业场景提供分流。

### 案例页

- 案例公开标题和内部真实标题分开管理。
- 客户名、Logo、项目图片已授权或匿名处理。
- 每个案例包含背景、挑战、方案、成果、相关产品和相关方案。
- 未确认成果不写精确数字。
- 案例列表支持行业、客户类型、产品服务筛选。

### 联系页

- 电话、手机、邮箱、地址、二维码全部复核。
- 表单字段完整，隐私政策勾选有效。
- 提交成功和失败状态可见。
- 表单接收人和线索分配流程已确认。

## 6. 设计验收

- 首页首屏 3 秒内能理解公司定位和主要能力。
- 视觉方向符合“平台驾驶舱型为主，工程现场型与研发底座型辅助”。
- 不使用大量抽象蓝色科技背景替代真实素材。
- 设计稿覆盖桌面端和移动端。
- 导航桌面端单行显示，高度不超过 80px。
- 首页 8 个模块至少使用 4 种不同布局结构。
- CTA 文案统一，主 CTA 使用“预约咨询”。
- 产品卡片、方案卡片、案例卡片有统一组件规则。
- 证书、奖项、Logo 展示克制，不做密集堆砌。
- 移动端无文字遮挡、按钮换行、图片裁切失焦、表格溢出。

## 7. 前端与 CMS 验收

### 前端

- 页面路由和 Sitemap 一致。
- Header、Footer、Mega Menu、按钮、卡片、表单等组件可复用。
- 首页模块内容来自 CMS 或结构化数据，不硬编码。
- 图片组件预留宽高，避免 CLS。
- 关键首屏图设置优先加载或预加载。
- 非首屏图片懒加载。
- 表单有前端校验和服务端校验。
- 404、500、空状态和加载状态完整。
- 外链使用安全属性。

### CMS

- Page、Product、Solution、Case、Resource、Honor、Asset、Lead 模型已建立。
- SEO 字段在后台可维护。
- 案例授权状态可控制前台展示。
- 首页精选产品、方案、案例可排序。
- 图片 alt、裁切焦点和授权状态可维护。
- 表单线索可导出或进入 CRM，具体方式需业务确认。

## 8. 性能验收

建议指标：

| 指标 | 目标 |
|---|---:|
| LCP | 小于 2.5s |
| INP | 小于 200ms |
| CLS | 小于 0.1 |
| 首屏图片 | 已压缩，尺寸合理 |
| JS 包体 | 避免不必要的大型动画和图表库 |
| 字体加载 | 使用 font-display: swap 或等效策略 |

检查项：
- 首页首屏主图文件大小受控。
- 视频不自动加载大文件，优先使用封面。
- 动效只使用 transform 和 opacity。
- 移动端低网速下仍能先看到文字和 CTA。
- 第三方统计、客服、地图等脚本延迟加载。

## 9. 可访问性验收

- 页面有明确语义结构，H1 唯一。
- H2、H3 层级不跳跃。
- 导航、Mega Menu、Tab、表单可键盘操作。
- focus-visible 状态清晰。
- 文本与背景对比度符合可读性要求。
- 图片 alt 描述真实内容。
- 表单错误提示和必填项可被识别。
- 动效支持减少动态效果。
- 移动端触控区域不小于 44px。

## 10. 技术 SEO 验收

- `sitemap.xml` 已生成并包含第一批上线页面。
- `robots.txt` 配置正确，不误屏蔽正式页面。
- 每页有 canonical。
- 旧 URL 已配置 301 重定向。
- 页面状态码正确，正常页面返回 200。
- 404 页面可用，并能回到首页或核心栏目。
- OG 图存在，分享预览正常。
- 页面标题和描述不重复。
- 图片 alt 不为空且不堆关键词。
- 内链完整，产品、方案、案例、资源之间互相支撑。
- 若接入统计工具，PV、咨询点击、表单提交事件可追踪。

## 14. 不允许带病上线

以下问题出现任一项，不建议上线：

- 首页核心数字未经确认。
- 联系方式、二维码或表单不可用。
- 客户 Logo 或案例图片授权不清。
- 平台截图包含敏感数据。
- 移动端首屏 CTA 不可见。
- 导航缺少“首页”或桌面端换行。
- 旧站重点页面无重定向。
- SEO 标题和描述为空或大量重复。
- 关键页面存在明显错字、OCR 错字或占位文案。
- 表单没有隐私政策确认。
- 生产环境仍有测试案例、测试电话或测试邮箱。
